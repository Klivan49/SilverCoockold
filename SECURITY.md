# Security

Документ для разработчиков и будущих агентов. Обновлять при изменении модели
доступа, провайдеров AI или источников данных.

## Секреты

- Все секреты живут только в `.env` (права `600`), который в `.gitignore`.
- Запрещено коммитить: `TELEGRAM_BOT_TOKEN`, `LLM_API_KEY`, `PROXY_URL` с
  логином/паролем, `TELEGRAM_CHAT_IDS`/`ADMIN_IDS` (это не секрет, но лишнее).
- В логах и ошибках токены/ключи маскируются. `safe_error()` и `mask_*()`
  обязательны для новых сообщений об ошибках.
- Ключи AI имеют срок действия. OpenCode Go ключ `oc_sk_...` уже истекал:
  при `401 api_key_expired` AI уходит в fallback. Проверять срок и ротацию.
- При утечке: остановить сервис, отозвать ключ в провайдере/`@BotFather`,
  выпустить новый, обновить `.env`, перезапустить, проверить логи.

## Telegram

- Один бот-токен = один poller `getUpdates`. Два демона с одним токеном дают
  `409 Conflict` и перебивают кнопки/команды.
- Команды и кнопки разрешены только `TELEGRAM_ADMIN_IDS`.
- `/id` доступен любому, чтобы новый человек мог прислать ID владельцу.
- Бот не пишет продавцам и не делает массовых рассылок.
- При подозрении на спам/бан: остановить, проверить `alerts`, снизить частоту.

## AI и данные

- В AI отправляются только публичные данные объявления: заголовок, описание,
  цена, категория, регион, фотографии товара.
- Не отправлять: имя/телефон/username продавца, переписку, `.env`, токены,
  локальные пути, данные других объявлений.
- OpenCode Go / DeepSeek: ZDR 0 дней по документации провайдера.
- Gemini 4 Argon Contributor в Go может использовать данные для обучения.
  Для публичных фото Kufar это допустимо, но не отправлять туда документы,
  лица, номера, личные вещи вне товара.
- Фото товара — публичные изображения Kufar. Не сохранять их дольше, чем нужно
  для анализа; кэш изображений не обязателен.
- При смене провайдера проверить политику retention/training и обновить этот
  документ.

## Kufar и закон

- Используется внутренний endpoint Kufar; публичного API нет. Он может
  измениться/заблокировать IP.
- Только личный низкочастотный мониторинг. Без обхода капчи, без массовых
  сообщений, без перепродажи персональных данных.
- Не создавать нагрузку: последовательные запросы, паузы, backoff на 429.
- Пользовательские соглашения Kufar и локальные законы — ответственность
  владельца. При претензии — остановить сбор.

## Доступ к хосту

- Сервис работает как systemd user unit, без открытых сетевых портов.
- UI — локальный Tkinter, не сетевой.
- `.env` и `data/` не публиковать. Бэкапы БД могут содержать историю
  объявлений; хранить локально.
- Для второго человека — отдельный Telegram-бот/токен, а не общий доступ к
  серверу.

## Инциденты

1. Остановить `silverwatch.service`.
2. Отозвать скомпрометированные ключи.
3. Проверить `git log`, `git grep` на секреты, `logs/app.log`.
4. Ротировать `.env`, перезапустить.
5. Записать инцидент в этот файл/CHANGELOG.
